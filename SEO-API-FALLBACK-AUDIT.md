# DGU SEO, API and Fallback Content Audit

**Audit date:** 24 October 2026  
**Scope:** Current source tree and route/data-generation code. No project code, configuration, content or existing file was changed for this audit. This report is the only new file.

## Scope and verification limits

- Inspected all 19 `app/**/page.tsx` route entry files, root layout/configuration, route identity/data sources, and the API adapters and rendering components referenced by those routes.
- The route inventory comprises 15 non-dynamic file-route patterns plus 4 dynamic patterns. Current source data enumerates 490 `/[contentSlug]/` paths, 104 `/programs/[programSlug]/` aliases, 8 `/schools/[schoolSlug]/` aliases, and 52 `/news/[articleSlug]/` article paths. This is **669 source path entries** before resolving possible URL collisions/aliases; the query-based legacy viewers accept unbounded query values and are not included in that count.
- Source coverage is complete for those declared route families. It does not prove each static-export file was generated or deployed. A production host/canonical origin is not established in this repository.
- **Runtime routes verified: 0.** No browser, build/export, deployed site, or live API request was run. This avoids generating/changing build output and avoids making authenticated POST requests with credentials not explicitly supplied for this audit. All API response-dependent behavior and final rendered HTML must therefore be validated at runtime.
- The pre-existing worktree had modifications before this audit. Those were left untouched.
- Evidence below is code-level unless explicitly labelled otherwise. “Correct metadata” means correctly declared by the route code, not verified in a browser’s rendered `<head>`.

**Most consequential result:** Program, school, admission, article and faculty API data is fetched by client components. API-provided title/description values, where parsed, are not returned by a server `generateMetadata` function and are applied with `document.title`/DOM mutation only after hydration. The static route metadata therefore remains the initial HTML metadata. The API fields do not set canonical, Open Graph or Twitter metadata.

**Repository-wide metadata gaps:** No `metadataBase`, `alternates.canonical`, `robots`, `openGraph`, or Next.js `twitter` metadata declaration was found in `app/` or relevant components. Root metadata defines only a title and generic description. All pages are consequently without a source-defined canonical, explicit robots policy, OG tags or Twitter card tags.

## E. Prioritised Findings

### Critical

1. **API-backed dynamic metadata is not present in the initial generated/server HTML.**  
   The program/school route entries export generic static `metadata`; API values are parsed in `parseAcademicInfo` and applied in `AcademicApiPage` from a `useEffect` using `document.title` and DOM mutation. Admissions follows the same client-only pattern. News articles and faculty profiles also set `document.title` only in client effects, and no route calls `generateMetadata` with the fetched record. With static export enabled outside development, these API results cannot populate the initial page metadata through the current metadata path. This is a **confirmed code integration defect**; actual deployed `<head>` output and crawler behavior were not runtime-tested.  
   **Evidence:** `next.config.ts:5-9`; `app/programs/[programSlug]/page.tsx:8-9`; `app/schools/[schoolSlug]/page.tsx:8-9`; `components/AcademicApiPage.tsx:260-269`; `components/AdmissionPage.tsx:37-44`; `app/news/[articleSlug]/page.tsx:7-14`; `components/NewsDetailPage.tsx:83-88`; `components/FacultyProfilePage.tsx:20`.

### High

1. **Generic titles and inherited generic descriptions on API-driven dynamic routes.**  
   The 104 program aliases use one title (“Programme”), the 8 school aliases use one title (“School”), news article aliases use “News & Updates”, and local admission/faculty-profile routes special-case to generic titles. The root description is inherited unless a route declares its own; the dynamic metadata function returns no description for these records. API metadata does not repair the initial static metadata.  
   **Evidence:** `app/layout.tsx:5-8`; `app/[contentSlug]/page.tsx:12-19`; `app/programs/[programSlug]/page.tsx:9`; `app/schools/[schoolSlug]/page.tsx:9`; `app/news/[articleSlug]/page.tsx:7`.

2. **Hostel gallery always combines fixed static photos with API photos.**  
   `referencePhotos` is concatenated unconditionally with `content.photos`, so API data does not replace the static set and static images remain when API images are present. Whether this is a stale fallback or approved supplemental imagery is not provable from source.  
   **Evidence:** `components/HostelLifePage.tsx:15-25, 143-144`.

3. **The homepage API's `news` value is parsed but not consumed.**  
   The homepage uses only `startupSuccess` and `higherEducation` from `HomepageData`; `NewsUpdatesSection` issues its own news requests. This is a confirmed unused response field, but not a confirmed user-visible omission because the page renders a separate API-fed news section.  
   **Evidence:** `components/homepage-api.ts:4-14`; `app/page.tsx:61-81, 167`; `components/NewsUpdatesSection.tsx:45-60`.

### Medium

1. **Canonical metadata is missing across all routes.** No source-defined canonical exists. Deployment base path and trailing-slash behavior are known, but the production origin is not. Several program aliases share API target slugs; absent canonical consolidation creates a duplicate-URL risk, but duplicate rendered content is not confirmed.
2. **Open Graph and Twitter metadata are missing throughout.** No route or root layout defines OG title/description/URL/image or Twitter card fields.
3. **No explicit robots directives are defined.** Next.js defaults may allow indexing, but no intentional per-route `index`/`noindex` policy is expressed in source. This is reported as missing policy, not as a claim that the effective robots behavior is blocked.
4. **Page-specific descriptions are absent on many routes.** Route titles may override the root title, but descriptions merge from the same generic root value. API-backed routes whose API description is empty retain the previous/root description because client effects do not clear it.
5. **Legacy redirects and canonical URL normalization are client/development-only.** Admission-process redirect and news/academic history normalization do not establish server redirects or canonical tags; the program/news rewrites are development-only.

### Low

1. **Intentional static presentation needs content-owner confirmation.** Hostel reference photos, international hero defaults, and club approved presentation media are source-confirmed static/API mixes, but source alone cannot prove whether they are current or approved.
2. **Fixed homepage placement video labels need confirmation.** They always render as primary homepage content; they are not conditioned as an API fallback.
3. **Static local content freshness is unknown.** The 490 generated local-page records render static JSON as primary content. This audit does not classify them as stale or unintended API fallbacks.
4. **Runtime validation remains outstanding.** API contracts require POST requests and API keys for most feeds; response shape, API availability, browser console errors, generated export tags, and crawler-visible metadata remain unverified.

## Canonical and route behavior details

- `next.config.ts` sets `basePath: ''` and `trailingSlash: true` (`:8-9`); `components/site-base.ts:1` uses the same internal base path. This establishes internal path shape, not a production origin.
- Development rewrites include `/news/:articleSlug/` to `/news/` and `/programs/:programSlug/:recordId/` to `/program-detail/` (`next.config.ts:11-15`). Those are gated by `NODE_ENV === 'development'`; production config uses static export.
- News article URL normalization (`NewsDetailPage`) and academic identity/query normalization (`AcademicQueryPage`) execute in client effects. `/admission-process/` also redirects in a client effect. They do not constitute verified HTTP redirects.
- `dgu.ac.in` in `dgu-api-transport.ts` is the API origin (`:9`), not a declared canonical website base. Do not infer the production canonical as `https://dgu.ac.in/...` or as a root-domain URL without deployment confirmation.
- The `canonical` field read by the older `program-info-api.ts` parser is not proof of canonical output and was not found connected to the active academic route renderer.
